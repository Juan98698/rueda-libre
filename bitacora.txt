========================================
JUSTIFICACIÓN DE CONTROLES DEL FORMULARIO
========================================
1. Tipo de bicicleta (Radio buttons - input type="radio"):
   Se eligieron botones de radio porque son opciones mutuamente excluyentes (el cliente solo puede elegir un tipo de bicicleta principal). Al compartir el mismo atributo name="tipo_bicicleta", el navegador garantiza que solo se seleccione una opción a la vez.

2. Fecha del alquiler (input type="date"):
   Se eligió el campo de tipo fecha para que el navegador despliegue un selector de calendario nativo y estandarizado, evitando errores de tipeo y formatos ambiguos por parte del cliente.

3. Comentarios (textarea):
   A diferencia de un campo de texto simple de una sola línea, textarea permite al cliente ingresar texto multilínea con saltos de renglón para aclaraciones o solicitudes especiales.

COMPROBACIÓN DE HERENCIA EN DEVTOOLS (STYLES Y COMPUTED)
========================================================================================================
Objetivo de la prueba:
Verificar en el navegador cómo viajan los estilos desde el elemento padre (<body>) hacia los elementos 
hijos (<p>, encabezados) mediante el mecanismo natural de herencia en cascada de CSS.
Herramientas utilizadas:
- Google Chrome DevTools (Panel "Elements" -> subpaneles "Styles" y "Computed").
- Elemento inspeccionado: etiqueta de párrafo <p> en index.html.
--------------------------------------------------------------------------------------------------------
1. PROPIEDAD QUE SÍ SE HEREDA: 'color' (o 'font-family')
--------------------------------------------------------------------------------------------------------
- Declaración en el padre (body):
  color: var(--color-azul-noche);  /* #14213D */
  font-family: var(--fuente-texto); /* 'Open Sans', sans-serif */
- Evidencia en DevTools (Styles):
  Al inspeccionar el <p>, la propiedad no está escrita directamente en su regla, sino agrupada 
  bajo la sección "Inherited from body".
- Valor en DevTools (Computed):
  El navegador resuelve el valor computado final del texto del párrafo como rgb(20, 33, 61) 
  y la tipografía renderizada como "Open Sans".
- Justificación técnica:
  Las propiedades relacionadas con el texto (color, tipografía, interlineado) se heredan por diseño 
  en CSS. Esto asegura consistencia visual en todo el documento sin necesidad de repetir reglas 
  en cada párrafo o lista.
--------------------------------------------------------------------------------------------------------
2. PROPIEDAD QUE NO SE HEREDA: 'background-color' (o 'margin' / 'padding')
--------------------------------------------------------------------------------------------------------
- Declaración en el padre (body):
  background-color: var(--color-crema); /* #FAF6EF */
- Evidencia en DevTools (Styles):
  La propiedad 'background-color' NO aparece listada en la sección "Inherited from body" del párrafo <p>.
- Valor en DevTools (Computed):
  Al buscar 'background-color' en la pestaña Computed del <p>, su valor computado es:
  rgba(0, 0, 0, 0)  (es decir: 'transparent').
- Justificación técnica:
  Las propiedades del modelo de caja (margin, padding, border) y los fondos (background-color) 
  NO se heredan por defecto. Si un fondo se heredara, cada elemento hijo crearía una capa de color 
  opaca redundante sobre la anterior. El párrafo se ve color crema únicamente porque su fondo es 
  transparente y permite ver el fondo del elemento que está detrás (el <body>).

   

RESOLUCIÓN DE CONFLICTO DE ESPECIFICIDAD Y ESTADOS DE INTERACCIÓN


1. DESCRIPCIÓN DEL CONFLICTO ENCONTRADO
--------------------------------------------------------------------------------------------------------
Un compañero intentó aplicar un estilo para destacar la página activa mediante las reglas:
  #menu a { color: var(--color-gris); }
  .activo { color: var(--color-verde); font-weight: 600; }

Problema visual:
Al cargar el sitio, el enlace con la clase "activo" no se mostraba verde; continuaba viéndose gris.
En DevTools (panel Styles), la declaración 'color: var(--color-verde)' aparecía tachada con una línea.

2. CÁLCULO TÉCNICO DE ESPECIFICIDAD (ID, CLASE, ELEMENTO)
--------------------------------------------------------------------------------------------------------
El algoritmo de cascada de CSS resuelve colisiones entre reglas mediante la tupla (a, b, c):
- Columna 'a' (IDs): 100 puntos de peso.
- Columna 'b' (Clases, atributos y pseudoclases): 10 puntos de peso.
- Columna 'c' (Elementos/etiquetas y pseudoelementos): 1 punto de peso.

Comparativa de los selectores en conflicto:
- Selector '#menu a':
  * IDs: 1 (#menu)
  * Clases: 0
  * Elementos: 1 (a)
  * Vector de especificidad: (1, 0, 1) -> Peso: 101 puntos.

- Selector '.activo':
  * IDs: 0
  * Clases: 1 (.activo)
  * Elementos: 0
  * Vector de especificidad: (0, 1, 0) -> Peso: 10 puntos.

Diagnóstico:
El selector '#menu a' gana por tener mayor especificidad ((1, 0, 1) > (0, 1, 0)) gracias a la 
presencia del ID '#menu'. Por esta razón, el navegador descarta el color definido en '.activo'.

3. SOLUCIÓN IMPLEMENTADA (SIN USAR !important)
--------------------------------------------------------------------------------------------------------
Se elevó la especificidad del selector activo vinculándolo al contexto del menú:
  #menu a.activo { color: var(--color-verde); font-weight: 600; }

- Nuevo vector de especificidad para el estado activo:
  * IDs: 1 (#menu)
  * Clases: 1 (.activo)
  * Elementos: 1 (a)
  * Vector: (1, 1, 1) -> Peso: 111 puntos.

Resultado:
(1, 1, 1) supera a (1, 0, 1), aplicando correctamente el color verde y la tipografía seminegrita
sin recurrir a malas prácticas como '!important' o estilos en línea.

4. ACCESIBILIDAD Y FOCO VISIBLE (WCAG 2.4.7)
--------------------------------------------------------------------------------------------------------
- Navegación (#menu a): se añadieron estados :hover (color azul noche y subrayado) y :focus con 
  outline de 2px en verde ruta y outline-offset de 3px para usuarios de teclado.
- Llamada a la acción (.boton-cta): fondo verde ruta (#1E7A4F) con texto blanco (#FFFFFF), 
  ratio de contraste 5.31:1 (Cumple WCAG AA). Foco resaltado con outline naranja (#F39A2B).
- Formulario de reservas: se garantizó foco visible en input, select y textarea con borde y outline 
  contrastante al navegar con Tab.


EXPERIMENTO DE MEDICIÓN DEL MODELO DE CAJA (BOX-SIZING) EN DEVTOOLS

Elemento analizado:
Etiqueta <article> (tarjeta de servicio) en index.html.
Propiedades aplicadas:
- width: 47%
- padding: var(--espacio-md) (1rem = 16px por lado)
- border: 1px solid var(--color-gris) (1px por lado)
--------------------------------------------------------------------------------------------------------
1. MEDICIÓN CON box-sizing: content-box (Comportamiento por defecto del navegador)
--------------------------------------------------------------------------------------------------------
Valores obtenidos en DevTools (pestaña Computed):
- Content (ancho del contenido): 451.2px (equivalente al 47% del contenedor de ~960px)
- Padding (izq + der): 16px + 16px = 32px
- Border (izq + der): 1px + 1px = 2px
- Ancho total ocupado en pantalla = 451.2px + 32px + 2px = 485.2px.
Impacto visual observado:
El padding y el borde se sumaron por fuera del ancho declarado. Debido a estos 34px adicionales, 
las tarjetas exceden el espacio de la fila y la segunda tarjeta se desborda y cae a la siguiente línea.
--------------------------------------------------------------------------------------------------------
2. MEDICIÓN CON box-sizing: border-box (Reseteo universal aplicado)
--------------------------------------------------------------------------------------------------------
Valores obtenidos en DevTools (pestaña Computed):
- Ancho total asignado a la caja: 451.2px (exactamente el 47% declarado)
- Padding (izq + der): 16px + 16px = 32px (absorbidos internamente)
- Border (izq + der): 1px + 1px = 2px (absorbidos internamente)
- Content resultante disponible para el texto/imagen: 451.2px - 32px - 2px = 417.2px.
Impacto visual observado:
La caja respeta estrictamente el ancho asignado del 47%. Ambas tarjetas conviven perfectamente 
en la misma fila sin desbordamiento ni saltos inesperados.
